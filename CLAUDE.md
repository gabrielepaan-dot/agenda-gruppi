# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It documents the **current state** of the app so a fresh session doesn't need to re-explore the codebase from scratch. See section 9 for the rule on keeping it that way.

## Project

Agenda Gruppi — a local-only PWA (also packaged as a native Android app via Capacitor) for a climbing coach to plan and run group training sessions, with an integrated gym timer (Tabata/EMOM/AMRAP) featuring hybrid voice/beep audio. Single user, Android phone only, Italian UI, no backend/account/cloud — all data lives in IndexedDB on-device. The full functional spec is `spec-agenda-gruppi.md` in the repo root — it is the source of truth for scope, but a few implementation details have since diverged from it (flagged in section 7).

## 1. Stack tecnico

- **Svelte 5** in runes mode (`$state`, `$derived`, `$props`, `$derived.by` — no legacy `export let`/stores) + **TypeScript** + **Vite 8**.
- **Dexie** (`src/lib/db.ts`) wraps IndexedDB; schema is versioned via `db.version(n).stores(...)`, with `.upgrade()` migrations at v6, v7, and v8 (v9 is a plain rename, no `.upgrade()` needed — see section 4).
- **svelte-dnd-action** for drag-to-reorder: exercises within a circuit (`CircuitForm.svelte`), rows within the Esercizi list (`NotesList.svelte`), the three top-level Note/Esercizi/Circuiti section cards within an allenamento (`AllenamentoEditor.svelte`), and exercises within a category in the eserciziario (`Eserciziario.svelte`) — four independent zones, never nested into the same zone. `NotesList.svelte`, `AllenamentoEditor.svelte`'s section cards, and (since 2026-07-27, see section 7) `CircuitForm.svelte` use plain `dndzone` (whole row is the drag surface — the library's own `mousedown`/`touchstart` handler already skips starting a drag when the press lands on a nested `<input>`/`<button>`/`<select>`/contenteditable, since those all expose a `.value`/`isContentEditable` the handler checks for, so a row's own remove button stays a clean tap with zero extra code); `Eserciziario.svelte` still uses the library's `dragHandleZone`/`dragHandle` action pair instead (`dragHandle` on the row's `≡` handle only, not the whole row) — don't reintroduce a `dragHandleSelector` option on any zone, it doesn't exist on this version's `Options` type and fails `svelte-check`.
- **Capacitor** (`@capacitor/core`, `@capacitor/android`) wraps the built web app into a native Android shell; native project lives in `android/`.
- **@fontsource/inter** bundled locally (not Google Fonts CDN) — the app must work with zero connectivity in the gym.
- No component-framework routing — `src/App.svelte` just switches between top-level screens by tab state (`$state<NavTab>`).
- No automated test suite. Verification is done by driving the Vite dev server (or the deployed preview) in a browser and inspecting IndexedDB/console directly.

### Commands

```bash
npm run dev         # Vite dev server
npm run build        # production build to dist/
npm run preview      # serve the production build locally
npm run check        # svelte-check + tsc --noEmit (no test suite exists)
npm run cap:sync     # build + copy dist/ into the Capacitor Android project
npm run cap:open     # open the Android project in Android Studio
```

The Android native project does **not** read from the source tree live — `npm run cap:sync` must be run (copies `dist/` into `android/app/src/main/assets/public`) before rebuilding in Android Studio.

### Deploy (Cloudflare Pages)

The repo is pushed to GitHub (`github.com/gabrielepaan-dot/agenda-gruppi`) and connected to **Cloudflare Pages** for automatic deploys: every push to `master` triggers a build (`npm run build`, output dir `dist`, `NODE_VERSION=22`) and publishes to `agenda-gruppi.pages.dev`. This is the fast iteration loop for bugfixing from the phone — open the URL in Chrome, "Add to Home Screen" for a PWA-like icon, reload after each deploy. No Capacitor rebuild needed for this loop; the APK is only for final/offline-verified installs. **Caveat**: data entered via the `.pages.dev` PWA lives in that browser's IndexedDB — it does **not** sync with the native APK's storage, they're separate origins/storage buckets.

## 3. Navigazione

Bottom nav has **5 tabs** (`BottomNav.svelte`): Oggi, Agenda, Allenamenti, Esercizi, Timer. (`spec-agenda-gruppi.md` still says "4 voci" — that line is stale, see section 7. Also note: the tab and screen were formerly labeled "Standard" — renamed to "Allenamenti" for the user-facing label/header only, the `AllenamentiStandard.svelte` filename and internal `Standard*` type/identifier names are unchanged. The separate "variant" naming (`StandardVariant` type/table/component, `ownerType: 'variant'`) that used to lag behind the "allenamento" UI wording was fully renamed to match on 2026-07-27, see section 7 — the code identifiers and the UI word are now the same.)

- **Oggi** (`Oggi.svelte`) — auto-detects today's group(s) via `slotsForDate`; on "double days" (Wed/Thu) shows a pill switcher between the day's two groups, never both at once. Auto-provisions today's `Session` via `ensureSessionForDate` (duplicates the most recent past session for that group if one exists, else creates an empty one). Shows the "last time" card and circuit list; tapping anything opens `SessionEditor`. Read-mostly — all editing is delegated. **Limitation**: only ever operates on *today's* date, no date picker.
- **Agenda** (`Agenda.svelte`) — flat, reverse-chronological list of **all** sessions across all groups, today's entry highlighted. Tapping opens `SessionEditor`. **Limitation**: no way to create a session for an arbitrary future date from here — sessions only come into being via Oggi's auto-provisioning or via "duplicate to next week" from inside an existing session.
- **Allenamenti** (`AllenamentiStandard.svelte`) — 2-level drill-down: group → allenamento (flat list, no intermediate category level — collapsed 2026-07-25, see section 7). The group list also shows each group's day(s) of the week, derived from `WEEKLY_SCHEDULE`, joined with a comma when a group meets more than once. CRUD-complete on `Allenamento`: create via the single FAB (picking a `date` from a `<select>` constrained to the group's scheduled weekdays, see below), or via "save current session as allenamento standard" from `SessionEditor`; edit via `AllenamentoEditor`; delete cascades its circuits. Each allenamento card shows its `date` (formatted via `formatShortDate`) plus its `tipologie` pills. `AllenamentoEditor` has **no** apply-to-session action (the "▶ Oggi"/"▶ Prossima lezione" chips were removed 2026-07-26, see section 7); `applyAllenamentoToSession` still exists in `standardService.ts` but is currently unused. **Limitation**: allenamenti can't be manually reordered within a group's list (only circuits inside one, and — since 2026-07-27 — the Note/Esercizi/Circuiti section cards inside one, can).
- **Esercizi** (`Eserciziario.svelte`) — list grouped by pattern category, FAB to add, tap to edit via `ExerciseForm` (name, category, Core subcategory if applicable, optional quality, voice recording). CRUD-complete. Deleting an exercise removes its voice recording but leaves the dangling id in any circuit's `exerciseIds` — shown as `—` wherever the name is looked up (matches the spec's "disappears from history silently" intent). **Note**: the old settings-gear entry point to a phrase/voice library is gone from this screen — voice profile management moved to the Timer screen (see section 7). A Tutti/Forza/Potenza filter chip row sits below the topbar (2026-07-26): a specific filter hides exercises with no `quality` set and hides categories left empty by the filter; "Tutti" (default) shows everything. Each category is independently drag-reorderable (manual `order` field, see section 4) via its own `dragHandleZone`, and each card shows a colored left-border accent from `PATTERN_CATEGORY_COLORS[cat].bg` so category is identifiable while scrolling (see section 7).
- **Timer** (`Timer.svelte`, embedded mode) — standalone timer: pick format (Tabata/EMOM/AMRAP), edit intervals via tap-to-open bottom sheets (time-kind rows use a scrollable MIN/SEC wheel picker, iOS-style; count-kind rows like Cicli/Round still use a plain number input), save/apply/delete reusable `TimerPreset`s ("I miei workout"), pick voice (system TTS voice or a `VoiceProfile`) and announce toggles, then "Avvia" → `TimerRunner`. Each saved preset card also has its own "▶ Avvia" button that applies the preset and starts it immediately (separate from the "✓" circle, which only applies the preset into the current setup form without starting). The same component is reused **non-embedded** as a per-circuit launcher (opened from the ▶ button in `SessionEditor`/`AllenamentoEditor`) — in that mode format/params are read-only (they come from the `Circuit`), only voice/announce settings remain editable. CRUD-complete for `TimerPreset`s only in standalone mode.

## 5. Moduli chiave

- **Timer engine** (`src/lib/timerEngine.ts`) — timestamp-driven, not tick-counted: `buildTabataTimeline`/`buildEmomTimeline`/`buildAmrapTimeline` build a flat `TimerPhase[]` upfront; `TimerEngine` steps through it on a 200ms `setInterval`, computing remaining time from an absolute `phaseEndTime` each tick to avoid drift. `buildTabataTimeline` tags `rest`/`rest_cycle` phases with the same `round`/`cycle` as the `work` phase they follow (not just `work` phases), so the UI can read remaining-round/cycle counts off any phase without peeking ahead. The final 3-2-1 countdown in the last `min(3, duration)` seconds of `work`/`rest`/`rest_cycle`/`interval`/`amrap` phases (and of `prepare`) is **always** beeped via `TimerAudio.playCountdownBeep` (short-short-long, never spoken) — this is unconditional and independent of voice settings; `work` was added to this set (`CUE_KINDS` in `timerEngine.ts`) 2026-07-27 to announce the imminent switch to rest, see section 7 — as a side effect Tabata's final `work` phase (which has no trailing `rest`/`rest_cycle`, going straight to `done`) now also gets this countdown before ending, closing a previously-documented gap where Tabata alone had no trailing cue window. Separately, `maybeCue`/`speakUpcoming`/`announceCompletion` still speak the phrase/exercise-name preview ("lavora"/"riposa"/exercise name/"completato") once per cue window when voice announcements are enabled; the two are no longer mutually exclusive (beep always plays, voice preview plays on top when active) — previously voice replaced the beep entirely. `pause()`/`resume()` freeze/restore the countdown by snapshotting the remaining seconds and recomputing `phaseEndTime` on resume (same drift-avoidance trick as the initial start); `TimerRunner.svelte` exposes this as a Pausa/Riprendi button next to Stop. `buildTabataTimeline`'s round count per cycle is `exerciseIds.length` when a circuit has linked exercises, but falls back to `TabataParams.genericRounds` (default 8) when `exerciseIds` is empty — this is what makes the standalone Timer tab's Tabata format actually loop instead of collapsing to `[prepare, done]` (with `totalRounds`/`totalCycles` in `TimerRunner.svelte` mirroring the same fallback). `Timer.svelte`'s `tabataRows` only shows the extra "Round" wheel-picker input when `(circuit?.exerciseIds.length ?? 0) === 0` — a circuit-linked Tabata still derives its round count silently from the exercise list, unchanged. Each `work` `TimerPhase` can also carry an `exerciseName?: string` (parallel to `exerciseId`, sourced from `Circuit.freeText`, see section 7) used to voice/display a free-text circuit entry that has no real `exerciseId` to look up.
- **Audio** (`src/lib/timerAudio.ts`) — `TimerAudio` class: synthesized beep via Web Audio (`AudioContext` oscillator, `beep(long?)` — `long` makes the final countdown tick a longer tone), TTS via Web Speech API (`it-IT`, optional system voice by `voiceURI`), and a hybrid lookup for phrases/exercise names that prefers a personal `VoiceRecording` (looked up by profile for phrases, globally for exercises) and falls back to TTS. `playCountdownBeep(remaining)` is the dedicated 3-2-1 countdown method (never speaks numbers).
- **TimerRunner UI** (`src/lib/TimerRunner.svelte`) — running-timer screen, rebuilt to: a header row (format name + total workout time remaining, color-matched to the current phase: green while working, red while resting/preparing); a full-width colored `phase-banner` (phase name + big countdown, green for work/interval/amrap, red for rest/rest_cycle/prepare); a smaller `next-banner` previewing the upcoming phase's name+duration (hidden once there's no next phase before `done`); the exercise list (unchanged); and a 3-column `stats-row` — **Round rimasti** (blue, left, tabata/emom only) / pause-resume circular button (center) / **Cicli rimasti** (yellow, right, tabata only) — followed by the Stop button. "Round rimasti"/"Cicli rimasti" are `totalRounds/totalCycles - phase.round/cycle + 1`, so they only decrement when a new round/cycle's `work` phase starts (holding steady through the following rest). AMRAP shows neither side stat, just the centered pause button.
- **Voice recording** (`VoiceRecorder.svelte`) — generic MediaRecorder-based record/play/delete widget parameterized by a `target` discriminated union (`{type:'exercise', exerciseId}` or `{type:'phrase', phraseKey, profileId}`); used inside both `ExerciseForm.svelte` and `VoiceProfiles.svelte`.
- **Voice profiles** (`VoiceProfiles.svelte` + `voiceProfiles` table) — lets you create multiple named profiles (e.g. different people), each owning its own recording for the 4 fixed phrases (prepara/lavora/riposa/completato). Reached via a gear icon next to "Voce" inside the Timer setup screen.
- **Timer presets** ("I miei workout", `TimerPreset` table, UI inside `Timer.svelte`) — reusable named timer configs (format+params), usable only from the standalone Timer tab; **not** wired into `CircuitForm` (see TODO).
- **Wake lock** (`wakeLock.ts`) — `WakeLockManager` wraps the Screen Wake Lock API and re-acquires it on `visibilitychange`, since Android releases the lock when the tab backgrounds/foregrounds.
- **Esercizi editor** (`NotesList.svelte`) — numbered-list editor bound to `Session.esercizi`/`Allenamento.esercizi` (renamed from a free-text `Note` field 2026-07-26; the component filename/internal shape are unchanged, only the label/placeholder/field it's wired to). Renders a numbered list: each row is a plain `<input>` with a drag handle (`≡`) + badge showing `index + 1` (never persisted — purely positional) grouped inside a `.grip` wrapper (widened 2026-07-27 — bigger gap, larger `≡` glyph, horizontal padding around the grip — to make the row easier to grab for drag on a phone; row height is unaffected since the extra padding is horizontal/small-vertical only, still shorter than the input's own height), and a ✕ remove button, plus a "+ Aggiungi riga" button that appends a row and focuses it. Pressing Enter inside a row's `<input>` (2026-07-27) does the same thing inline — `handleKeydown` calls `e.preventDefault()` then `insertLineAfter(i)`, which splices a new blank row directly after the current one, commits, and focuses it via the same `tick()`+`inputEls[i]?.focus()` pattern as `addLine` — so typing a list of exercises never requires touching the "+" button. Reordering is drag-and-drop (`svelte-dnd-action`'s `dndzone`, `flipDurationMs: 150`, same pattern as `CircuitForm.svelte`'s exercise list) rather than ▲/▼ buttons — `onconsider` updates the local array live during drag, `onfinalize` also commits. When the component mounts with an empty `value`, it seeds 8 blank rows (a bare textarea/list would otherwise start empty); if `value` already has content, only those rows are shown, no padding — this replaced the old three quick-add buttons (6/8/10), which are gone. Storage is unchanged: the component is `bind:value`-driven (a single `\n`-joined string) with an `onCommit` callback fired after every structural change (add/remove/reorder) and on row blur (not on every keystroke) — the parent does its own Dexie write in `onCommit`. Splitting/joining on `\n` is lossless for the common case but means a literal newline typed mid-row would (if it were possible via a plain `<input>`, which it isn't) be indistinguishable from a row break — not a real-world concern given `<input>` can't contain newlines. Takes an optional `showHeader` prop (default `true`, added 2026-07-27) that hides its own internal "Esercizi" `.header-row` label — used by `AllenamentoEditor` where the surrounding section-card already renders that label, to avoid a duplicate heading; `SessionEditor` doesn't pass it, so its own inline usage is unchanged.
- **Note libere** — `Session.notes`/`Allenamento.notes` (2026-07-26) is a separate plain `<textarea>` (no numbering/structure). Persists on blur via its own `saveNotes` Dexie write, independent of the Esercizi list's `saveEsercizi`. In `SessionEditor` it's still a plain field above the Esercizi list; in `AllenamentoEditor` (2026-07-27) it lives inside its own reorderable section card, see section 7.
- **Date pickers for `Allenamento`** (`groups.ts`'s `formatShortDate`/`candidateDatesForGroup`) — `candidateDatesForGroup(groupId, weeksBack=8, weeksForward=26)` generates the list of ISO dates, restricted to that group's scheduled weekday(s) (same `WEEKLY_SCHEDULE` source of truth as `nextScheduledDate`), used to populate the `<select>` in AllenamentiStandard's "Nuovo allenamento" sheet, `AllenamentoEditor`'s date-change sheet, and `SessionEditor`'s "save as allenamento standard" sheet. Callers that show an *existing* record's date manually union it into the candidate list first (`base.includes(allenamento.date) ? base : [...base, allenamento.date].sort()`) so a date outside the generated window (e.g. a migrated/legacy value) still appears as a selectable, non-blank option instead of silently falling off the list. `formatShortDate` itself was extended 2026-07-27 from a short "gio 30" form to a full "giovedì 30 luglio" form, backed by two new lookup tables in `groups.ts`: `WEEKDAY_NAMES` (exported, 0–6 → domenica...sabato — also now the single source of truth `AllenamentiStandard.svelte`'s `daysForGroup` imports instead of its own former partial 1–4 copy) and a module-private `MONTH_NAMES` (0–11 → gennaio...dicembre). Every call site listed above picked up the new format automatically, no call-site changes needed.

## 6. Convenzioni

- Svelte 5 runes only; no `export let`/stores anywhere.
- Discriminated unions for variant types (`VoiceRecordingTarget`, `VoiceMode`/`VoiceSelection`, `TimerPhase['kind']`).
- Italian for all user-facing strings/labels; English for code identifiers, file names, comments.
- Recurring pattern for any taxonomy: define the union type + a `*_LABELS: Record<T, string>` + (where relevant) a `*_COLORS: Record<T, {bg,text}|string>` together in the same `*Types.ts` file (see `circuitTypes.ts`, `types.ts`).
- Full-screen editors (`SessionEditor`, `AllenamentoEditor`, `CircuitForm`, non-embedded `Timer`) share a `position:fixed; inset:0` "screen" shell with a topbar (✕ close + centered `<h1>`). Smaller create/edit flows (`ExerciseForm`, allenamento creation) instead use a dimmed `.overlay` + rounded-top `.sheet` bottom-sheet pattern with a handle-bar.
- Every editor communicates via `onSaved`/`onClose`/`onDeleted` callback props — no event dispatching, no global store; the parent screen re-fetches from Dexie after the callback instead of the child mutating shared state.
- **Known gotcha**: `$state` objects/arrays are reactive Proxies. Passing one directly into `db.table.add()`/`.put()` throws `DataCloneError`. Always spread into plain objects/arrays (`{ ...tabata }`, `[...exerciseIds]`) immediately before any Dexie write — see `circuitService.copyCircuits` and `CircuitForm.save` for the pattern.
- **Known gotcha**: `BottomNav` is `position:fixed; bottom:0; height:80px; z-index:60` with an opaque background, and stacks above same-context siblings with `z-index:auto` regardless of DOM order (positive z-index always wins). Any screen-level FAB must sit at `bottom: 96px` or more with its own `z-index` (e.g. 65) to clear it — `bottom: 24px` places the FAB entirely underneath the navbar, making it invisible and unclickable (this was the bug behind the Esercizi/Allenamenti FABs, fixed in `Eserciziario.svelte`/`AllenamentiStandard.svelte`).
- Fixed dark theme only (CSS variables in `src/app.css`, no light mode / OS-preference switching).

## 7. Decisioni di design prese

- **Circuit has no standalone library/list screen.** It always belongs to an owner (`ownerType: 'session'|'allenamento'` + `ownerId`) and is created/edited inline from whatever owns it, because `Session` and `Allenamento` are structurally identical containers (ordered circuits + notes). `circuitService.ts` exists purely to keep the owner-type filtering consistent across both callers.
- **`Allenamenti` collapsed from 3 levels to 2, and `warmup` was dropped entirely (2026-07-25).** The category level (`standardCategories` table, group → category → allenamento) was removed — `Allenamento` (then still named `StandardVariant`, see below) now carries `groupId` directly, so the screen is just group → flat allenamento list; the `v7` migration back-fills `groupId` from each allenamento's old category before dropping the table (see section 4). The `Riscaldamento` textarea/field was removed from both `Session` and `Allenamento` (and from `Oggi`'s "last time" preview) — a coach-driven simplification, not something the spec called for. Historical `warmup` string values in existing rows are left untouched in IndexedDB (harmless, just unread) rather than being explicitly stripped.
- **Groups and weekly schedule are hardcoded** (`groups.ts`) — intentionally out of scope for an editor per the spec. The `Pro` group was split (2026-07-25) into two separate `GroupId`s, `pro_mer` and `pro_gio` (both `name: 'Pro'`, distinguished only by color and by which weekday slot in `WEEKLY_SCHEDULE` references them), so Wednesday and Thursday Pro sessions/allenamenti no longer share the same `groupId` — no migration was needed since no data existed under the old `pro` id yet. **The `GROUPS` object's key insertion order matters** (2026-07-27): `AllenamentiStandard.svelte`'s group list iterates `Object.values(GROUPS)`, so the literal's key order is the display order. Keys are ordered chronologically by weekday (`corso_base` mon, `intermedi_corda` tue/thu, `pro_mer` wed, `corso_intermedio` wed, `pro_gio` thu) rather than any other convention — `corso_intermedio` was moved before `pro_gio` to fix a wrong display order. Keep this in mind before reordering or adding a `GroupId`.
- **Timer engine is timestamp-driven**, not tick-counted, specifically to avoid drift over long AMRAP/EMOM durations.
- **Voice library was redesigned mid-project**: it used to be a single fixed `PhraseLibrary.svelte` (one recording per phrase, reached from a settings gear in `Eserciziario`'s topbar). It's now `VoiceProfiles.svelte` — N named profiles × 4 phrases each — reached from the Timer setup screen instead. The `db.version(6)` upgrade migrates any pre-existing recording into a default "Voce salvata" profile so nothing is lost. Rationale (inferred from the shape of the change): support different people's voices being selectable per timer run, not just the coach's own.
- **Bottom nav grew from 4 to 5 tabs.** Timer is now a first-class tab (standalone timer + preset library) rather than a button living inside Oggi. `spec-agenda-gruppi.md`'s "Bottom nav a 4 voci" line is stale on this point — don't treat it as current truth.
- **Per-circuit configurable rest structure was simplified in implementation.** The spec calls for the rest type (only-between-rounds vs. also-between-exercises) to be configurable per circuit; `buildTabataTimeline` currently always inserts a `rest` phase between every exercise and a separate `rest_cycle` between cycles, with no toggle to suppress the inter-exercise rest.
- **Exercise voice recordings are global, phrase recordings are per-profile** — an intentional asymmetry: exercise pronunciation doesn't need to vary "by coach voice" the way the four fixed cue phrases do (those exist specifically to let different people's voices run a session).
- **`Circuit.name` is now optional (2026-07-26).** `CircuitForm.save()` no longer blocks on an empty name (`Circuit.name` itself is still typed `string`, just allowed to be `''`). Wherever a circuit's name is displayed (`SessionEditor`/`AllenamentoEditor` cards), an empty name falls back to `circuitSummary(c)` as the title, with the subtitle line suppressed in that case (to avoid showing the same string twice).
- **`Tipologia` moved from `Circuit` to `Session`/`Allenamento`, and became multi-select (2026-07-26).** Previously a single required field on `Circuit` (3 exclusive buttons in `CircuitForm`), it's now `tipologie: Tipologia[]` on the session/allenamento as a whole, edited via 3 independent toggle buttons (not a segmented control — any combination of 0–3 can be active) in `SessionEditor`/`AllenamentoEditor`, using `TIPOLOGIA_COLORS` for each button's own active state. The per-circuit tipologia pill is gone from circuit cards. Rationale (coach-driven): tipologia describes the session/allenamento as a whole, not each circuit inside it. No Dexie migration was needed (neither the old nor the new field was ever indexed) — pre-existing circuits simply lose their `tipologia` value silently (extra field, unread), and pre-existing sessions/allenamenti read `tipologie` as `undefined` until first touched (all read sites guard with `?? []`, all write sites default to `[]`).
- **`Allenamento.name` renamed to `date` (2026-07-26, back when the type was still called `StandardVariant`).** An `Allenamento` is still a freely reusable template — the `date` is only the *default label* shown in the allenamenti list/topbar and pre-filled in the "Nuovo allenamento"/date-change pickers, **not** a constraint on which sessions it can be applied to. The `date` field is chosen via a `<select>` restricted to the owning group's scheduled weekdays (`candidateDatesForGroup`, section 5), defaulting to today if today is a valid weekday for that group, else to `nextScheduledDate(groupId)`. This required a real Dexie migration (`db.version(8)`, section 4) since `name` was indexed and is gone; the `standardService.saveSessionAsAllenamento` signature changed from `(session, name, notes)` to `(session, esercizi, notes, date = today)` accordingly (further extended for the `esercizi` split below) — check current call sites before assuming the old parameter order.
- **`Session.notes`/`Allenamento.notes` split into `esercizi` + `notes`, and `NotesList` became drag-reorderable (2026-07-26).** The field that used to hold the numbered exercise-list string was renamed `esercizi`; a new, separate `notes` field was introduced as genuine free text (plain `<textarea>`, no per-row structure). `NotesList.svelte` (still that filename) now labels itself "Esercizi", seeds 8 blank rows on an empty value instead of requiring the old 6/8/10 quick-add buttons (removed), and reorders via `svelte-dnd-action` drag-and-drop instead of ▲/▼ buttons (matching `CircuitForm`'s exercise-list pattern) — see section 5. Screen order in `SessionEditor` is Tipologia (buttons shrunk) → Note (textarea) → Esercizi (`NotesList`) → Circuiti; in `AllenamentoEditor` these last three are now independently reorderable section cards (2026-07-27, see below). `applyAllenamentoToSession`/`saveSessionAsAllenamento` (`standardService.ts`) and `duplicateSessionTo`/`ensureSessionForDate` (`sessionService.ts`) all updated to read/write both fields, defaulting to `''` when reading a pre-existing record that predates this split (`session.esercizi ?? ''`) since no Dexie migration was run for this rename — **this default is not optional**: Svelte 5 throws a runtime `props_invalid_value` error ("Cannot do `bind:value={undefined}` when `value` has a fallback value") if an explicitly-`undefined` field is ever bound directly into `NotesList`'s bindable `value` prop, so every read site needs the `?? ''` guard, unlike the `tipologie ?? []` pattern which only needs the guard at usage, not at state-init time.
- **`AllenamentoEditor`'s apply-to-session chips removed, delete button repositioned (2026-07-26, back when the file was still `StandardVariantEditor.svelte`).** The "▶ Oggi"/"▶ Prossima lezione" chip row (and its `applyToDate` handler, `appliedDate` state, `nextDate` const) were removed — applying an allenamento to a session is no longer available from that screen. `applyAllenamentoToSession` remains in `standardService.ts` (currently unused, kept for potential future use) since `saveSessionAsAllenamento` — the reverse direction, still used by `SessionEditor`'s "salva come allenamento standard" — was not touched. Separately, "Elimina allenamento" moved from inside `.content` to a sibling of it (still inside `.screen`): since `.screen` is a flex column and `.content` is `flex:1; overflow-y:auto`, a sibling button after it sits pinned at the bottom of the screen with no `position:fixed` needed, with a `border-top` to separate it from the scrollable content above (same technique as the topbar's `flex-shrink:0`).
- **`StandardVariant` fully renamed to `Allenamento`, end to end (2026-07-27).** The "variant" naming had lagged behind the "allenamento" UI wording since the `date` rename above; this closed that gap in one pass: the `standardTypes.ts` interface `StandardVariant` → `Allenamento`; the Dexie table `standardVariants` → `allenamenti` (`db.version(9)`, a bare `{ standardVariants: null, allenamenti: '++id, groupId' }` rename with **no** `.upgrade()`, since — unlike every earlier rename in the migration history — no data existed under the old name yet, see section 4); `CircuitOwnerType`'s `'variant'` literal (`circuitTypes.ts`) → `'allenamento'`, propagated through every `getCircuitsFor`/`deleteCircuitsFor`/`copyCircuits` call site and the `ownerType="variant"` prop passed to `CircuitForm`; `standardService.ts`'s `applyVariantToSession`/`saveSessionAsVariant` → `applyAllenamentoToSession`/`saveSessionAsAllenamento`; and `StandardVariantEditor.svelte` was renamed to `AllenamentoEditor.svelte` with all its internal `variant*` locals (`variant` prop, `variantDate`, etc.) renamed to `allenamento*`, matching `AllenamentiStandard.svelte`'s renamed `variants`/`openVariant`/`createVariant`/etc. locals. **Pre-existing `circuits` rows with `ownerType: 'variant'`** (from before this rename, if any exist on a real device) are now orphaned — `getCircuitsFor('allenamento', ...)` won't find them — same accepted-tradeoff shape as the `tipologia`/`warmup` "silently unread" precedents elsewhere in this history, justified here by the explicit no-data-yet premise.
- **`AllenamentoEditor` redesigned around three reorderable section cards, `formatShortDate` extended to a full date, and `NotesList`'s drag handle widened (2026-07-27).** Three related but separate changes landed together: (1) `formatShortDate` (`groups.ts`) now returns e.g. "giovedì 30 luglio" instead of "gio 30", via two new lookup tables — exported `WEEKDAY_NAMES` (0–6, all seven days; `AllenamentiStandard.svelte`'s `daysForGroup` now imports this instead of keeping its own former partial 1–4 copy) and a private `MONTH_NAMES` (0–11) — every caller picked up the new format automatically. (2) `NotesList.svelte`'s row handle+badge got a bigger touch target (wrapped in a `.grip` with more gap/padding, larger `≡` glyph) without changing row height, and gained an optional `showHeader` prop (default `true`) so a parent that already renders its own "Esercizi" label (see below) can suppress the component's internal one. (3) `AllenamentoEditor`'s Note/Esercizi/Circuiti fields — previously three plain stacked fields — became three `.section-card`s (`var(--bg-elevated)`, 20px radius, 18px padding, reorderable via a second, independent `dndzone` over `{id: AllenamentoSection}` items distinct from `NotesList`'s own internal row-reordering `dndzone` and from `CircuitForm`'s exercise-list `dndzone`) whose order is persisted per-allenamento in the new `sectionOrder` field (section 4) via `onfinalize`. The Tipologia toggle row deliberately stayed outside this card system (no background, no card) — the spec explicitly wanted it visually lighter/distinct from the three reorderable cards, not promoted to look the same.
- **Small coach-driven UI batch (2026-07-26): `NotesList` seeds 1 row not 8, `CircuitForm`'s timer-format picker collapsed into a compact bottom footer, `Eserciziario` gained a quality filter + per-category drag reorder + category-colored card accents.** `NotesList.svelte`'s `linesFromValue` now seeds a single blank row on empty value (was 8) — the "+ Aggiungi riga" button is the only way to add more. `CircuitForm.svelte`'s "Formato timer" section (previously a large `.format-tabata`/`.format-minor` tab row + 2-column `.params-grid`, with Tabata's active state hardcoded to a lime `#c4ff4d`) was replaced by a single `.timer-footer` block: three equal compact `.pill` tabs (all three now share one active style, `var(--accent)` background/border, white text — Tabata is no longer visually special-cased) plus a `.params-inline` flex-wrap row holding every param for the selected format, still fully editable, nothing summarized to text-only. `.timer-footer` uses `margin: auto -20px 0` inside `.content` (a flex column) so it's pinned to the bottom of the screen when the fields above are short, with a `var(--bg-navbar)` background and `border-top` to separate it from the scrollable content. See section 4 for the `Eserciziario` changes (`Exercise.order`, `db.version(10)`) and section 3 for the filter/drag/color-accent behavior.
- **`CircuitForm`'s exercise list and "Aggiungi esercizio" picker gained the same category-color accents as `Eserciziario` (2026-07-27).** Each `.exercise-row` (selected exercises in the circuit) now gets a 4px `border-left` colored via `PATTERN_CATEGORY_COLORS[ex.category].bg` (looked up per row through `exercisesById`, falling back to `transparent` if the exercise was deleted), matching `Eserciziario.svelte`'s `.card` pattern exactly. In the picker bottom sheet, `.picker-section-label` gained the same small colored `.dot` before the category name, and `.picker-row` gained the same colored `border-left`. Purely visual — no new state, no schema change, `PATTERN_CATEGORY_COLORS`/`types.ts` untouched.
- **`CircuitForm`'s `.exercise-row` shape aligned to `Eserciziario`'s `.card` pattern (2026-07-27).** `border-radius` went from `var(--radius-sm)` to `var(--radius-lg)`; the row switched from `align-items:center` with a uniform `gap` to `align-items:stretch`, giving the drag handle its own `padding: 0 4px 0 10px` and wrapping the name+remove-button pair in a new `.row-body` div carrying `padding: 14px 16px 14px 6px` — the exact `.drag-handle`+`.card-body` split `Eserciziario.svelte` already used. The "Aggiungi esercizio" picker's `.picker-row` was deliberately left untouched: it's a flat menu-list (no radius, no elevated background, `border-bottom` dividers) rather than a card grid, so it was never diverging from the `.card` shape in the first place.
- **`CircuitForm`'s timer-format choice reduced to Tabata only (2026-07-27).** The `.format-pills` (Tabata/Emom/Amrap) selector and the Emom/Amrap param blocks were removed from the editor; only the Tabata param fields (`Prepara`/`Lavoro`/`Riposo`/`Cicli`/`Rip. cicli`) remain, always shown. `save()` now always writes `timerFormat: 'tabata'` — the `emom`/`amrap` state (and `Circuit.emom`/`Circuit.amrap`, still required fields per section 4's schema) are kept and still written on every save, just no longer user-editable, so they stay at their default values for any circuit created or re-saved through this form. No Dexie migration was needed and none of the "existing non-tabata circuit" fallback logic was built, because there was no pre-existing circuit data on the device at the time of this change (confirmed before implementing) — if a `circuits` row with `timerFormat: 'emom'|'amrap'` is ever encountered, `TimerRunner.svelte`/`timerEngine.ts` still fully support running it unchanged (that code was not touched), it just can't be *created* or have its format *changed* via `CircuitForm` anymore; opening and saving such a circuit in the form will silently convert it to `'tabata'`. This change is scoped to `CircuitForm`/`Circuit` only — the standalone Timer tab (`Timer.svelte`, `TimerPreset`s) is untouched and still offers all three formats, since presets are unrelated to circuits.
- **`CircuitForm`'s exercise-list drag switched from whole-row `dndzone` to handle-only `dragHandleZone`/`dragHandle`, matching `Eserciziario.svelte` (2026-07-27).** ***Superseded the same day*** — see the later 2026-07-27 entry below ("switched (again) from handle-only to whole-row"): the handle turned out to still be too small a target on Android, so this got reverted back to whole-row `dndzone`, this time with a more robust anti-disappearance fix. Kept here for history. Two reported problems drove this original change: (1) on Android touch, dragging from anywhere on the row competed with native scroll/text-selection gestures, giving a ~1s perceived delay before drag actually started; (2) a release outside a valid drop target could occasionally make a row vanish instead of returning to the list. Fix for (1): `touch-action: none`/`user-select: none` now live on `.handle` only (not the whole `.exercise-row`), matching `Eserciziario`'s already-working pattern, so only the small `≡` handle competes with scroll, not the row's text/remove-button area. Fix for (2) is a defensive guard in `onfinalize` (`handleFinalize` in `CircuitForm.svelte`): it diffs the finalized item list's ids against the pre-drag `selectedItems` ids and re-appends any that went missing, so a drag can reorder but — regardless of what `svelte-dnd-action` reports — can never make a row disappear; the ✕ button (`removeItem`) remains the only real deletion path. `onconsider` is untouched (still a plain live-update passthrough) since the shadow-item mechanics during an active drag already preserve id/count.
- **`CircuitForm` gained free-hand "testo libero" exercise entries (2026-07-27).** The "Aggiungi esercizio" picker sheet now has a text input + "Aggiungi" button above the categorized exercise list, letting the coach add an ad hoc row (e.g. "Stretching 5'") that is **not** persisted to `db.exercises` or any other table — it only exists inside that one circuit. Modeled as `SelectedItem.freeText?: string` in `CircuitForm.svelte` (alongside the existing `exerciseId`); on save, `Circuit.exerciseIds[i]` is `0` (a placeholder — Dexie auto-increment ids start at 1, so `0` never collides with a real exercise) for a free-text slot, and the new parallel `Circuit.freeText?: string[]` (section 4) carries the actual text at that same index, `''` for real-exercise slots. `circuitService.copyCircuits` carries `freeText` through session↔allenamento circuit copies. Downstream consumers that used to resolve exercise names purely via `exerciseIds` were updated to fall back to `freeText[i]` first: `Timer.svelte`'s `circuitExerciseList` (setup-screen preview + the array passed to `TimerRunner` as `exerciseNames`), and `timerEngine.ts`'s `buildTabataTimeline`, which now also takes the `freeText` array and stamps each `work` `TimerPhase.exerciseName` from it — `TimerEngine.speakUpcoming` prefers `exerciseName` (via `TimerAudio.speakText`, plain computer TTS) over the `exerciseId`-based `speakExercise` lookup when present. A free-text entry therefore behaves like a real exercise everywhere it's displayed or spoken during a timer run, it just can never have a voice *recording* (only a real `Exercise` row can own one).
- **`CircuitForm`'s picker-sheet "Chiudi" button made a sticky footer (2026-07-27).** Previously the last element inside the `.sheet`'s single scrollable region, so it could be scrolled out of view behind a long exercise list. `.sheet` no longer scrolls itself; a new `.picker-scroll` wrapper (`flex:1; min-height:0; overflow-y:auto`) around the free-text input + categorized list is now the only scrolling region, and `.btn-cancel` sits after it as a `flex-shrink:0` sibling spanning the sheet's full width with a `border-top` — always visible at the bottom of the sheet regardless of list length. Same "flex column, scrollable middle, pinned sibling footer" technique documented elsewhere in this section for `AllenamentoEditor`'s delete button — no `position:fixed` needed since the sheet already has a bounded `max-height`.
- **`SessionEditor`'s "↻ Duplica per {data}" button removed; "★ Salva come allenamento standard" + "Elimina sessione" made a sticky footer (2026-07-27).** The quick-duplicate-to-next-week action (and its `duplicateForNextWeek` handler, `duplicated` state) was dropped. This was `groups.ts`'s `nextWeekIsoDate`'s only remaining caller, so the function itself was deleted too (it's not part of any Dexie migration or other logic — just a plain date-math helper). `duplicateSessionTo` (`sessionService.ts`) is **not** dead code despite losing this call site — `ensureSessionForDate` still calls it internally for the auto-provisioning path. The two remaining action buttons moved out of the scrollable `.content` into a new sibling `.action-footer` (flex column, `border-top`, safe-area-aware bottom padding) — same sibling-footer pattern as `AllenamentoEditor`'s delete button and `CircuitForm`'s picker Chiudi above; no overlap-avoidance padding is needed on `.content` since the footer is a layout sibling, not a `position:fixed` overlay. The renamed `.btn-save-standard` class replaces the old shared `.btn-duplicate` style (visually unchanged, just no longer named after the removed feature).
- **Timer countdown beep extended to the end of `work` phases (2026-07-27).** `work` was added to `timerEngine.ts`'s `CUE_KINDS` set, so the existing 3-2-1 `playCountdownBeep` pattern (previously only before `rest`/`rest_cycle`/`interval`/`amrap`/`prepare`) now also fires in the last `min(3, duration)` seconds of every `work` phase, announcing the upcoming switch to rest. See section 5 for the knock-on effect on Tabata's final phase.
- **Timer now announces the rest-between-cycles duration by voice (2026-07-27).** When a `rest_cycle` `TimerPhase` begins, `TimerEngine.beginPhase` now speaks `` `Riposo ${durationSeconds} secondi` `` via `TimerAudio.speakText` (plain computer TTS), gated by the same `announce.frasi` toggle as other phase phrases. This **replaces** the generic `speakPhrase('riposa')` call for `rest_cycle` specifically (plain `rest` phases between exercises are untouched, still just "Riposa") — deliberately, since a per-profile voice recording is a static audio blob and can't include a dynamically-computed number, so a `rest_cycle` announcement always falls back to computer TTS now regardless of the active `VoiceSelection`. Calling both `speakPhrase('riposa')` and a separate duration utterance back-to-back was considered and rejected: `TimerAudio.speakText` calls `speechSynthesis.cancel()` before speaking, which would have clipped whichever utterance went first.
- **`CircuitForm`'s exercise-list drag switched (again) from handle-only to whole-row, and hardened against interrupted touch gestures (2026-07-27).** Two Android-reported problems drove this: (1) the `≡` handle was too small a drag target and forced a perceptible extra step before the drag actually engaged; (2) a row could vanish entirely if the touch gesture ended abnormally (release over another interactive element, or — the real culprit — the OS cancelling the gesture outright: incoming call, edge-swipe nav, notification shade, app backgrounded mid-drag). Fix for (1): swapped `dragHandleZone`/`dragHandle` back to plain `dndzone` on `.exercise-list` (see section 1) — the `≡` glyph is now purely decorative, and `.exercise-row` itself carries `touch-action: none`/`cursor: grab` (moved off `.handle`), so a press anywhere on the row starts the drag immediately with no touch delay configured, while the library's own nested-interactive-element check keeps the `✕` remove button a clean tap (verified directly: a synthetic `mousedown` on `.remove-btn` doesn't get `preventDefault()`-ed by the library's handler, while one on the row body does). Fix for (2) has two layers in `CircuitForm.svelte`: the existing `handleFinalize` id-diff guard now diffs against a `preDragSnapshot` (captured on the first `consider` event of a drag, i.e. the library's own `DRAG_STARTED` trigger) rather than just the live `selectedItems`, so it still catches a legitimate `finalize` that arrives with a doctored item set; and a new `forceEndStuckDrag`, wired to `window`'s `touchcancel`/`pointercancel`/`blur` and `document`'s `visibilitychange` (`$effect`-scoped add/remove), which handles the case `finalize` **never** fires at all — svelte-dnd-action only listens for `mouseup`/`touchend`, not `touchcancel`, so a cancelled gesture used to leave the drag permanently unfinished. `forceEndStuckDrag` first replays synthetic `touchend`/`mouseup` dispatches on `window` so the library's own drop-handling runs normally (safe to fire unconditionally — these are inert no-ops when no drag is pending/active, since the library only has listeners registered for them during those two states); as a last-resort net, a 300ms `recoveryTimer` then force-restores `selectedItems` from `preDragSnapshot` directly if the synthetic replay still didn't clear it. Verified in a live session by starting a real drag (mousedown+mousemove past the library's movement threshold) and firing `touchcancel`/`visibilitychange(hidden)` with no matching `mouseup` — in both cases the ghost dragged-element clone (`#dnd-action-dragged-el`) cleaned up and both rows survived, order intact.

## 8. Cosa manca / TODO noti

- Timer presets aren't surfaced or auto-suggested from `CircuitForm` when picking a circuit's timer format/params, even though the spec wants "choosing a recurring block type suggests its associated timer preset automatically." `TimerPreset` currently only lives inside the standalone Timer tab, disconnected from circuit creation.
- No per-circuit toggle for rest structure (only-between-rounds vs. also-between-exercises) — see section 7.
- Exercise photo/video attachments — explicitly deferred in the spec ("in futuro, non ora"), not started.
- No manual date picker to plan a session for an arbitrary future date — sessions only come into existence via `ensureSessionForDate` (today, automatic) or `duplicateSessionTo` (always the next occurrence of the same weekday).
- No automated test suite (verification is manual, via browser + IndexedDB inspection).
